# 能力完整性审计与路线图

> 2026-10-22 · 基于独立代码审计与端到端实测整理

这份文档回答一个比“功能列表”更重要的问题：**哪些能力是真的、哪些只是演示、下一阶段应该先补什么。**

## 1. 当前结论

### 已经真正可用

- 影像 DCT/QIM 水印、矢量坐标水印，含 JPEG 压缩、噪声、缩放恢复测试。
- 资产上传（多文件队列）、缩略图、详情、搜索/筛选/排序、收藏、合集、附件下载。
- 资产版本：上传新版本、历史下载、恢复旧版本；文件替换后强制退回草稿重新审核。
- 版本级存证：证书按文件版本签发，同一资产可有多个版本证书；新版本重置当前存证状态，历史证书保留并在证书页标注“历史版本”。
- 异步任务：水印/存证任务持久化到 `async_tasks`，后台 worker 执行，支持进度、去重、自动重试、手动重试、取消与超时对账；worker 定期写入 `worker_heartbeats`，后台“任务队列”页与 `/api/tasks/health` 展示在线 worker、最老排队任务、积压/离线/超时告警，`flask tasks status --check` 可直接用于容器健康检查；生产 compose 提供独立 worker 服务。
- 评论、回复、编辑、软删除；影像区域标注（版本绑定、类型、状态、解决/删除）。
- 双重授权审批状态机、合同文本、申请撤回。
- 分享链接（有效期、访问码、下载开关/次数）、证据链、下载台账、操作日志、待办已读。
- 通知渠道：站内 SSE 实时推送（Authorization 头鉴权、断线补发）、邮件偏好与分组、系统 Webhook（通用 JSON/企业微信群机器人、HMAC 签名、重试、SSRF 拦截）；后台仪表盘/通知渠道页显示投递计数。
- 授权范围执行：结构化使用目的/渠道/可下载格式/地域/下载次数随申请审批落库；下载时校验申报用途与地域，超范围返回 403 并写入台账（可筛选“超范围拒绝”）。
- 授权版本绑定：新授权记录签发时的文件版本；资产更新后旧授权不能直接下载新版本，需重新申请；换版会通知受影响的被授权方。
- 授权使用报表：状态/配额/超范围拒绝原因/下载趋势/版本待重审聚合，支持筛选和 CSV 导出。
- 多格式预览：图片/矢量缩略图、视频在线播放、PDF 内嵌预览、三维模型（GLB/GLTF/STL/OBJ）旋转缩放；预览按授权控制、不写下载台账。FBX/Office 文档仍为下载查看。
- 侵权线索：公开提交文件/链接/说明，服务端尝试水印匹配；后台可受理、确认或驳回，结果通知举报人与权利人，举报文件仅管理员可下载；管理员可批量上传最多 20 个文件做异步巡检，匹配项自动生成线索。
- JWT 双 Token、登出/改密失效、角色权限、公开接口限流。
- 园林档案维护、后台仪表盘真实统计、系统能力状态面板。

### 明确是“演示/可选”，不是默认真实能力

- **区块链**：默认 `BLOCKCHAIN_ENABLED=false`，交易哈希、区块号与证书为本地模拟数据；证书页和证据链会标注“本地模拟存证”。接入 FISCO BCOS 需配置节点、私钥与合约。
- **AI**：默认关闭，依赖模型与 API Key；未配置时接口返回 503，不会伪造“无侵权”结论。首页与 README 已改为“可选能力”。
- **OCR**：当前未实现，不在默认功能列表内。
- **调度器/备份**：默认关闭；生产需要外部 cron 或单独 worker。

## 2. 本轮已修复的高风险问题

- 水印后存证校验恒失败：证书指纹按原始文件计算，校验同时接受原始/水印派生文件。
- 已发布资产替换文件可绕过审核：新版本现在退回草稿，必须重新水印、提交发布并通过审核。
- Nginx 将 `/assets` 当静态目录，导致 Docker 下资产详情直达 404：构建产物改为 `static/`。
- 反向代理下全站共享限流桶：compose 开启 `TRUST_PROXY_HEADERS`，数据库/Redis/MinIO/后端端口限制在本机。
- 水印/提取/备份目录未持久化：compose 增加 watermarks、extracted、instance 挂载。
- 水印副本为 PNG 却按原扩展名下载：下载名跟随实际文件扩展名。
- 公开溯源/证书/水印核验泄露草稿或名不副实：公开溯源只命中已发布资产，证书页标注模拟模式。
- 权限过宽：license_admin/adm1/adm2 不能再改删他人资产；审批人不能审批自己的申请。
- 评论通知：自己资产收到新评论会出现在待办，链接直达讨论页签。
- 迁移体系：引入 Alembic baseline 与迁移测试，`init_db.py` 改为 `flask db upgrade`，旧库自动 stamp 基线。
- 分享下载台账：匿名分享下载写入 `share_downloads`，后台台账合并授权/分享渠道并支持筛选。
- 授权履约：撤销、续期、独家互斥、生效时间校验已落地；撤销/续期会通知被授权方。
- 事件通知：资产提交/审核结果、授权审批/撤销/续期写入事件表，与实时待办合并展示。
- 检索分面：标签、文件格式、上传日期范围、上传者筛选，附标签计数接口。
- 异步任务管线：水印/存证不再阻塞请求线程；任务落库、原子领取、失败重试与超时回收，资产详情与批量上传均通过任务队列执行。
- 版本级证书：`certificates.version_id` 绑定文件版本，`asset_id` 取消唯一约束；证书页与版本列表展示对应版本，新版本未重新存证时公开验证明确失败。
- 移除了从未部署的 Celery 任务入口，避免与持久化队列并行；`app/tasks.py` 改为队列兼容入口。
- 通知渠道：事件写入时同事务创建邮件投递行；用户可在账号设置按分组开启邮件，SSE 实时推送与断线补发已验证；SMTP 未配置时明确提示而不是伪造发送。
- 授权范围执行：用途、渠道、格式、地域、下载次数写入授权；下载接口核对申报范围并记录拒绝原因；历史授权字段为空时保持不限制。
- 下载台账区分成功/超范围拒绝，新增拒绝原因、申报用途与地域，后台可按结果筛选。
- 侵权线索流程：公开溯源页提交线索、水印匹配、后台研判与双方通知；线索文件限制类型与大小，仅管理员可下载；批量巡检通过异步任务队列执行。
- 授权版本绑定：审批时记录文件版本，下载校验版本一致性；历史授权保持兼容；换版通知与管理员待办联动。
- 授权使用报表：授权状态、配额、拒绝原因分类、近 N 天趋势与资产排行，支持版本过期筛选和 CSV 导出。
- 下载指纹：每个授权+资产生成一份可见页脚副本（保留原盲水印），下载台账记录指纹码；重复下载复用，不无限膨胀。
- 多格式预览：视频与 PDF 通过 blob 在线预览，按授权控制且不增加下载量；CSP 已放行 blob 媒体/框架。
- worker 运维：心跳落库、在线/离线判定、积压与超时告警、`flask tasks status --check` 与 compose 健康检查，避免“任务排队但无人消费”静默失败。
- 水印 ID 编码：重复份数按图像容量自适应（20/12/8/5/3/1），提取端兼容历史编码，改善批量巡检和高光区域的 ID 恢复率。

## 3. 仍然不够、需要下一阶段补齐

### P0 生产可用性

1. **备份可恢复**：SQLite 改用在线备份 API 并做完整性校验，PostgreSQL 恢复带 `ON_ERROR_STOP` 与单事务；`flask backup create/list/restore`、Docker 备份卷和 SQLite 回滚副本已具备，并有“备份→删数据→恢复→校验”的自动化回环测试；仍需在真实部署环境做一次完整恢复演练，并把备份复制到独立存储。
2. **存储抽象**：本地磁盘/MinIO 统一为 object key；补孤儿文件清理与文件级校验。
3. **独立 worker 运维**：已补 worker 心跳、队列健康度、积压/离线/超时告警与 compose 健康检查；仍缺多队列隔离与跨主机 worker 负载视图（当前按 worker 展示心跳与处理量）。

### P1 业务闭环

4. **超范围使用监测**：下载环节已校验申报范围并记录拒绝，也支持公开举报、批量文件巡检与后台研判；但互联网上的未授权副本仍需要人工提供文件/链接，缺少自动爬取与水印副本批量比对。
5. **通知渠道扩展**：已有站内 SSE、邮件与系统 Webhook；仍缺短信、企业微信应用消息（非群机器人）和按用户维度的 Webhook。SSE 每连接占一个 gthread 线程，大规模需要 Redis Pub/Sub 或独立推送服务。
6. **检索深度**：已支持标签/格式/日期/上传者分面，仍缺全文与向量检索；Milvus 主键类型与字符串资产 ID 不兼容。
7. **多格式预览**：视频、PDF 与 GLB/GLTF/STL/OBJ 已支持在线预览；FBX 与 Office 文档仍缺少预览/转码和缩略图；水印只覆盖 image/vector。
8. **逐次下载指纹**：当前每个授权+资产复用一份可见指纹副本；高频分发场景可进一步做逐次下载唯一指纹与副本生命周期清理。

### P2 体验与工程

9. 详情页仍偏大（约 2400 行），版本/分享弹窗尚未拆组件；`admin/layout.vue`、`upload.vue` 也可继续拆分。
10. 后台表格列设置、保存的搜索、更细的批量审批仍未做；已支持批量通过/驳回与当前页 CSV 导出。
11. 无障碍与移动端仍有零散问题（键盘可操作性、对比度、表格横滚）。
12. 默认演示账号密码仍需在部署时强制替换；生产 `.env` 应拒绝 `change-me-*` 示例密钥。

## 4. 建议的下一阶段顺序

1. 自动侵权巡检（水印副本批量比对）与通知渠道扩展（Webhook/企业微信）。
2. 授权使用报表与超范围趋势分析。
3. 全文/向量检索与多格式预览。
4. 备份恢复演练与存储抽象。
5. 后台批量能力（导出、列设置、保存的搜索）。

每一项的验收标准都应包含：真实端到端流程、失败路径、权限越权测试，以及 Docker 环境下的直达/刷新验证。
