# 能力完整性审计与路线图

> 2026-10-22 · 基于独立代码审计与端到端实测整理

这份文档回答一个比“功能列表”更重要的问题：**哪些能力是真的、哪些只是演示、下一阶段应该先补什么。**

## 1. 当前结论

### 已经真正可用

- 影像 DCT/QIM 水印、矢量坐标水印，含 JPEG 压缩、噪声、缩放恢复测试。
- 资产上传（多文件队列）、缩略图、详情、搜索/筛选/排序、收藏、合集、附件下载。
- 资产版本：上传新版本、历史下载、恢复旧版本；文件替换后强制退回草稿重新审核。
- 版本级存证：证书按文件版本签发，同一资产可有多个版本证书；新版本重置当前存证状态，历史证书保留并在证书页标注“历史版本”。
- 异步任务：水印/存证任务持久化到 `async_tasks`，后台 worker 执行，支持进度、去重、自动重试、手动重试、取消与超时对账；生产 compose 提供独立 worker 服务，后台 `/admin/tasks` 可查看队列并重试/取消。
- 评论、回复、编辑、软删除；影像区域标注（版本绑定、类型、状态、解决/删除）。
- 双重授权审批状态机、合同文本、申请撤回。
- 分享链接（有效期、访问码、下载开关/次数）、证据链、下载台账、操作日志、待办已读。
- JWT 双 Token、登出/改密失效、角色权限、公开接口限流。
- 园林档案维护、后台仪表盘真实统计、系统能力状态面板。

### 明确是“演示/可选”，不是默认真实能力

- **区块链**：默认 `BLOCKCHAIN_ENABLED=false`，交易哈希、区块号与证书为本地模拟数据；证书页和证据链会标注“本地模拟存证”。接入 FISCO BCOS 需配置节点、私钥与合约。
- **AI**：默认关闭，依赖模型与 API Key；未配置时接口返回 503，不会伪造“无侵权”结论。首页与 README 已改为“可选能力”。
- **OCR**：当前未实现，不在默认功能列表内。
- **调度器/备份**：默认关闭；生产需要外部 cron 或单独 worker。

## 2. 本轮已修复的高风险问题

- 水印后存证校验恒失败：证书指纹按原始文件计算，校验同时接受原始/水印派生文件。
- 已发布资产替换文件可绕过审核：新版本现在退回草稿，必须重新水印、提交发布并通过审核。
- Nginx 将 `/assets` 当静态目录，导致 Docker 下资产详情直达 404：构建产物改为 `static/`。
- 反向代理下全站共享限流桶：compose 开启 `TRUST_PROXY_HEADERS`，数据库/Redis/MinIO/后端端口限制在本机。
- 水印/提取/备份目录未持久化：compose 增加 watermarks、extracted、instance 挂载。
- 水印副本为 PNG 却按原扩展名下载：下载名跟随实际文件扩展名。
- 公开溯源/证书/水印核验泄露草稿或名不副实：公开溯源只命中已发布资产，证书页标注模拟模式。
- 权限过宽：license_admin/adm1/adm2 不能再改删他人资产；审批人不能审批自己的申请。
- 评论通知：自己资产收到新评论会出现在待办，链接直达讨论页签。
- 迁移体系：引入 Alembic baseline 与迁移测试，`init_db.py` 改为 `flask db upgrade`，旧库自动 stamp 基线。
- 分享下载台账：匿名分享下载写入 `share_downloads`，后台台账合并授权/分享渠道并支持筛选。
- 授权履约：撤销、续期、独家互斥、生效时间校验已落地；撤销/续期会通知被授权方。
- 事件通知：资产提交/审核结果、授权审批/撤销/续期写入事件表，与实时待办合并展示。
- 检索分面：标签、文件格式、上传日期范围、上传者筛选，附标签计数接口。
- 异步任务管线：水印/存证不再阻塞请求线程；任务落库、原子领取、失败重试与超时回收，资产详情与批量上传均通过任务队列执行。
- 版本级证书：`certificates.version_id` 绑定文件版本，`asset_id` 取消唯一约束；证书页与版本列表展示对应版本，新版本未重新存证时公开验证明确失败。
- 移除了从未部署的 Celery 任务入口，避免与持久化队列并行；`app/tasks.py` 改为队列兼容入口。

## 3. 仍然不够、需要下一阶段补齐

### P0 生产可用性

1. **备份可恢复**：需挂载备份卷、安装 `pg_dump`、启用调度器或外部 cron，并做恢复演练。
2. **存储抽象**：本地磁盘/MinIO 统一为 object key；补孤儿文件清理与文件级校验。
3. **独立 worker 运维**：compose 已提供 worker 服务，但还缺 worker 心跳、队列积压告警与多队列隔离。

### P1 业务闭环

4. **授权范围执行**：下载已校验生效时间、独家互斥、撤销/续期，但 usage_scope、territory 仍只记录不执行；也没有超范围使用监测。
5. **通知渠道**：已有事件正文与站内已读，但缺少邮件/SSE/推送，审核结果需要用户主动打开铃铛才能看到。
6. **检索深度**：已支持标签/格式/日期/上传者分面，仍缺全文与向量检索；Milvus 主键类型与字符串资产 ID 不兼容。
7. **多格式预览**：3D/视频/文档没有预览、转码和缩略图；水印只覆盖 image/vector。
8. **下载指纹水印**：所有下载共用同一水印文件，泄露副本只能定位到资产，不能定位到被授权人。

### P2 体验与工程

9. 详情页仍偏大（约 2400 行），版本/分享弹窗尚未拆组件；`admin/layout.vue`、`upload.vue` 也可继续拆分。
10. 后台表格列设置、导出、保存的搜索、批量审批仍未做。
11. 无障碍与移动端仍有零散问题（键盘可操作性、对比度、表格横滚）。
12. 默认演示账号密码仍需在部署时强制替换；生产 `.env` 应拒绝 `change-me-*` 示例密钥。

## 4. 建议的下一阶段顺序

1. 通知渠道（邮件/SSE）与 worker 心跳/积压告警。
2. 授权范围/地域执行与使用监测，版本级授权约束。
3. 全文/向量检索与多格式预览。
4. 备份恢复演练与存储抽象。
5. 后台批量能力（导出、列设置、保存的搜索）。

每一项的验收标准都应包含：真实端到端流程、失败路径、权限越权测试，以及 Docker 环境下的直达/刷新验证。
